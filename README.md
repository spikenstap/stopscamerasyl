# StopScam 2.1

Обновлён существующий Flutter-проект: текст, URL, телефон, QR и Android Call Screening. Интерфейс RU/KK, светлая/тёмная тема, локальная история до 200 записей.

## Запуск после скачивания с GitHub

Установите Flutter SDK и Android Studio с Android SDK. Проект проверен с Flutter 3.47.5 / Dart 3.13.4; Android minSdk 26. В проекте указан NDK 30.0.16248370.

```powershell
git clone https://github.com/spikenstap/stopscamerasyl.git
cd stopscamerasyl
Copy-Item .env.example .env
flutter pub get
flutter devices
flutter run
```

На macOS/Linux вместо Copy-Item используйте `cp .env.example .env`. Файл `.env` нужен для сборки, но не хранится в Git. Личная база номеров работает без сети. Для сетевых проверок настройте BACKEND_URL. Ключ LLM хранится только в backend/.env и не включается в APK. Сборка APK: `flutter build apk --debug`.

## Запуск на исходном компьютере

Android Studio → Open → папка `stopscam` с `pubspec.yaml`. Flutter SDK: `C:\flutter`. В Device Manager запустите Pixel_7; откройте `lib/main.dart` и нажмите Run.

Или в терминале папки проекта:

```powershell
C:\flutter\bin\flutter.bat pub get
C:\flutter\bin\flutter.bat run -d emulator-5554
```

Готовый `StopScam.apk` можно перетащить на запущенный Android-эмулятор. Это debug APK для проверки, подписанный локальным debug-ключом, не магазинный релиз.

## Личная база номеров (локальная версия)

Нижняя вкладка **«Номера» → «Добавить номер»**. Введите номер, название, заметку и выберите правило:
- **Наблюдать**: сохранить запись; само правило звонки не блокирует.
- **Блокировать**: личный чёрный список. Работает для звонков, переданных Android приложению, после выбора StopScam приложением для фильтрации звонков.
- **Разрешать**: личное исключение, имеет приоритет над репутационной блокировкой. Не подтверждает безопасность номера.

Карточка номера позволяет редактировать/удалять запись, проверить номер и добавить личную жалобу. Жалоба сама не включает блокировку. По умолчанию она остаётся локальной. Переключатель «Анонимно делиться жалобами на номера» в настройках разрешает отправку только номера и категории новых жалоб. Названия и заметки остаются на телефоне. Старые жалобы не отправляются; отключение не удаляет ранее отправленные. При ошибке сервера локальная запись сохраняется, сообщение объясняет неудачную отправку. Отметки, названия и заметки не отправляются в AI. Наставления доступны через «Настройки → Обучение».

SQLite `personal_numbers.db` хранит до 5000 номеров и отдельные записи жалоб. База общая для интерфейса и Android CallScreeningService, сохраняется между запусками. Очистка истории проверок не очищает номера; удаление приложения или его данных удаляет базу. Удаление номера удаляет его личные жалобы. В карточке отображаются последние 100 жалоб.

Меню ⋮ во вкладке «Номера»: импорт/экспорт CSV через системный выбор файла без разрешения на всё хранилище. Экспорт включает номера, названия, правила, категории и заметки, но не отдельные жалобы и не историю проверок. Храните файл приватно. UTF-8, до 8 МБ, до 5000 строк данных. Можно импортировать файл с одним номером в строке или таблицу:

```csv
phone,label,rule,category,note
```

Поддерживаются разделители запятая, точка с запятой, табуляция. `rule`: watch/blocked/trusted; `category`: unknown/advertising/suspectedFraud/harassment/other. Перед сохранением видны количество пригодных строк, ошибок и дубликатов. Уже существующие номера не перезаписываются. По умолчанию новые записи получают «Наблюдать». Восстановление правил из собственного экспорта включается отдельным флажком. Импорт транзакционный: ошибка записи отменяет весь пакет. При экспорте значения защищаются от исполнения формул в электронных таблицах.

База изначально пустая: сторонние списки и непроверенные обвинения не добавлялись. Общая репутация берётся из backend; личная база не синхронизируется. Неизвестный номер не объявляется мошенническим по его цифрам.

## Backend и настоящий AI

Настройки клиента (.env; без секретов):

```dotenv
BACKEND_URL=https://your-backend.example
USE_MOCK_AI=false
```

BACKEND_URL также задаётся через --dart-define=BACKEND_URL=... и имеет приоритет над .env. После изменения адреса пересоберите APK. Старые AI_API_KEY, AI_API_URL и PHONE_REPUTATION_API_KEY больше не используются: удалите их из локального клиентского .env перед сборкой, поскольку этот файл входит в assets.

Backend запускается по [инструкции](backend/README.md). Ключ LLM_API_KEY задаётся исключительно в backend/.env. Не присылайте ключ в чат. Без него backend возвращает ai_not_configured, приложение показывает ошибку настройки; выдуманных оценок нет.

При первом запуске приложение регистрирует устройство (POST /v1/auth/register). deviceId/deviceSecret хранятся через flutter_secure_storage, отдельно для каждого адреса backend. Access token хранится только в памяти, получается через /v1/auth/token и обновляется перед истечением срока. После 401 — одно обновление и один повтор, при 403 повторной регистрации нет. Параллельные запросы используют одно обновление. Ошибка регистрации не блокирует локальную базу; следующая сетевая проверка повторит попытку.

Анализ: POST /v1/analyze с type/content/language/localSignals; результат разбирается ScamAnalysis.fromJson. Личные названия и заметки не передаются. Текстовые QR отправляются как text, URL QR — как qr; в истории оба сохраняют тип QR. Контактные QR и пароли Wi-Fi остаются локальными.

В обычных сборках разрешён только HTTPS, перенаправления запрещены. Для локальной проверки debug APK есть явный ALLOW_INSECURE_BACKEND=true: HTTP разрешается только для частных/loopback IP и localhost. В release этот флаг не действует.

Отладочные примеры включаются только в debug явным USE_MOCK_AI=true, имеют маркировку и не служат fallback при сетевой ошибке. Risk Score — оценка признаков, confidence — уверенность в выводе, не вероятность мошенничества.

### Компьютер и телефон в одной сети

Компьютер может быть подключён кабелем к тому же роутеру. Узнайте его активный LAN IPv4 через ipconfig; не используйте адрес отключённого адаптера, WSL или VirtualBox.

```powershell
cd backend
$env:BACKEND_BIND_IP="192.168.123.34" # замените своим активным адресом
docker compose -p stopscam-local -f docker-compose.yml -f docker-compose.lan.yml up -d --build
Invoke-RestMethod "http://$($env:BACKEND_BIND_IP):8000/readyz"
cd ..
flutter build apk --debug --dart-define=BACKEND_URL=http://192.168.123.34:8000 --dart-define=ALLOW_INSECURE_BACKEND=true
```

Откройте http://АДРЕС:8000/healthz в браузере телефона — ожидается status:ok. Если Windows блокирует входящие соединения, в PowerShell администратора можно добавить правило только для TCP 8000, адреса компьютера и локальной подсети:

```powershell
New-NetFirewallRule -DisplayName "StopScam local backend" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -LocalAddress 192.168.123.34 -RemoteAddress LocalSubnet
```

Локальный HTTP не шифрует трафик; этот вариант для личной проверки в доверенной сети. Не пробрасывайте порт в интернет. Компьютер и Docker должны работать. При смене IP пересоберите APK с новым адресом. Остановка без удаления базы:

```powershell
cd backend
docker compose -p stopscam-local -f docker-compose.yml -f docker-compose.lan.yml stop
```

## Телефон и звонки

Номер нормализуется, например `87001234567` → `+77001234567`. Без службы репутации результат содержит «Недостаточно данных» и не содержит численной оценки. Можно добавить описание разговора: тогда AI анализирует именно это описание вместе с доступными данными номера.

Служба репутации использует общий backend: POST /v1/phone/check с `{"phoneNumber":"+77001234567"}` и токеном устройства. Ожидаемый JSON:

```json
{"status":"unknown","confidence":0,"confirmed":false,"source":"your-provider"}
```

`status`: `unknown`, `clear` или `flagged`; confidence 0..1; confirmed boolean; источник обязателен для clear/flagged. Дополнительный expiresAt — Unix-время в миллисекундах. Просроченные ответы отвергаются; кэш ограничен 24 часами. `flagged` — отметка провайдера, не придуманная AI репутация. Конкретная платная база не подключена и подписка не оформлялась.

Settings → «Защита от звонков» → «Выбрать StopScam…». Android покажет системный запрос. Роль выбирает пользователь. Без роли ручные проверки работают. Для роли нужен Android 10+ и её поддержка устройством.

CallScreeningService сначала учитывает личное правило из SQLite, затем локальный кэш репутации, заполненный ручными проверками номера. Сеть и AI до ответа системе не вызываются. Неизвестные номера пропускаются. Личное правило «Блокировать» действует независимо от переключателя репутационной автоблокировки. Последняя выключена по умолчанию и требует пользовательского включения, свежей подтверждённой отметки flagged и confidence ≥0.95. Системные ограничения означают, что сервис получает не все звонки: например, скрытые номера и контакты без READ_CONTACTS могут не поступать. Приложение не запрашивает READ_CONTACTS или READ_CALL_LOG.

Нативная очередь входящих хранит до 200 записей. Flutter импортирует их при запуске/возврате в приложение, сохраняет историю и только затем подтверждает импорт. Повторный импорт одного ID не создаёт дубликат. Уведомления разрешаются отдельно пользователем, содержимое приватное на экране блокировки.

## QR

Камера запрашивается при открытии QR-экрана. Есть фонарик, рамка, обработка отказа, настройки разрешения и повтор. После распознавания камера останавливается; повторные кадры не создают запросы. Анализ запускается кнопкой после предпросмотра.

Поддерживаются URL, текст, телефон, SMS, email, Wi-Fi, контакт, платёжные схемы и неизвестный формат. Пароли Wi-Fi и данные контактных карточек скрываются и не отправляются в AI. Платёжные данные отображаются, но никогда не исполняются. «Открыть ссылку» доступно после анализа; при высоком риске или низкой уверенности требуется дополнительное подтверждение. Автоматических переходов, звонков, SMS и платежей нет.

Для ручной проверки камеры на телефоне можно отсканировать изображения `previews/qr-safe.png` и `previews/qr-suspicious.png` с экрана компьютера. Для реального AI нужен ключ LLM на backend. В эмуляторе изображение поступает с виртуальной камеры, а не с камеры телефона.

## Проверки

```powershell
flutter clean
flutter pub get
dart format .
flutter analyze
flutter test
flutter build apk --debug
```

`dart format .` выполняйте после clean: длинные пути сгенерированных Android build-файлов на Windows могут мешать обходу каталогов. Для обычных правок можно форматировать `lib test integration_test test_driver`.

Оплачиваемые реальные запросы включаются явно:

```powershell
flutter test test/live_ai_test.dart --dart-define=STOPSCAM_LIVE_TEST=true
```

Тест проверяет пять разных запросов, структуру ответа и различие безопасных/подозрительных случаев. Он не фиксирует точные цифры модели и не выводит ключ. По умолчанию этот тест пропущен.

Проверка клиента с живым локальным backend без платных AI-запросов:

```powershell
$env:STOPSCAM_TEST_BACKEND_URL="http://192.168.123.34:8000"
$env:STOPSCAM_EXPECT_AI_UNCONFIGURED="true" # только если ключ LLM пуст
flutter test test/backend_live_test.dart --dart-define=STOPSCAM_BACKEND_TEST=true
```

Этот тест создаёт одно тестовое устройство, проверяет получение токена, повторный запуск с сохранёнными учётными данными и репутацию вымышленного номера. Жалобы не отправляет. Учётные данные хранятся только в памяти теста; Android Keystore нужно проверять на устройстве.

Для повторного запуска сервера есть `backend/start-local.ps1 -BindAddress ВАШ_IP`. Однократное правило брандмауэра добавляет `backend/allow-local-firewall.ps1 -BindAddress ВАШ_IP`, запущенный в PowerShell администратора.

Нативные тесты: `android/gradlew.bat :app:testDebugUnitTest`. Интеграционные тесты `integration_test` используйте на отдельном тестовом эмуляторе: Flutter может переустанавливать/удалять приложение, а сценарии создают и очищают тестовую историю. Не запускайте их поверх пользовательских данных.

Подробные результаты проверки и ограничения: `VALIDATION.md`.

Документация: [Android CallScreeningService](https://developer.android.com/reference/android/telecom/CallScreeningService), [RoleManager](https://developer.android.com/reference/android/app/role/RoleManager), [mobile_scanner](https://pub.dev/packages/mobile_scanner), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
