# StopScam: отчёт о переработке и проверках

Дата: 26 сентября 2026. Изменён существующий проект, новый проект не создавался.

1. **Найденные проблемы.** В поставленной версии режим mock был включён по умолчанию, AI-сервис возвращал один пример независимо от введённых данных; отсутствовали номер, камера QR, confidence и нативная проверка звонков. Модель истории поддерживала только численный риск, поэтому неизвестная репутация требовала отдельного представления.

2. **Источник 87.** Это было фиксированное `riskScore: 87` в mock-ветке `lib/services/scam_ai_service.dart` при `USE_MOCK_AI=true`, а не реальный ответ на каждое сообщение. Та же цифра ожидалась в старых UI-тестах. Поле результата в интерфейсе само брало число из модели.

3. **Что удалено.** Постоянный результат 87 и повторяемые объяснения из рабочего сервиса, старые неиспользуемые локализованные mock-причины и ожидания единой цифры в UI-тестах. Число 87 осталось только как произвольное значение в тестах парсинга/некорректного JSON: оно не является runtime fallback. Debug-примеры вынесены в `dev_fixtures.dart`, явно маркируются и различаются по признакам. Release игнорирует USE_MOCK_AI.

4. **Файлы.** Основные изменения: `models/analysis_type.dart`, `scam_analysis.dart`, `scan_history_item.dart`; `services/analysis_service.dart`, `scam_ai_service.dart`, `dev_fixtures.dart`, `phone_reputation_service.dart`, `call_bridge.dart`; `core/providers.dart`, `utils/url_utils.dart`, `phone_utils.dart`, `qr_content.dart`, `widgets/common.dart`; экраны home, scanner/controller, phone, QR, result, history, settings/call_protection; `app/app.dart`, `router.dart`, `theme/app_colors.dart`; обе ARB-локализации и сгенерированные локализации; pubspec/lock и `.env.example`. Android: MainActivity, CallStore/CallPolicy, StopScamCallScreeningService, manifest, зависимость JUnit. Добавлены/обновлены unit, widget, native и integration-тесты, README и инструкция запуска. Форматтер также привёл существующие Dart-файлы к единому стилю.

5. **Message Check.** Unified AnalysisService передаёт конкретный текст, язык, тип и извлечённые URL в настоящий HTTP AI-сервис. Строго валидируются score 0..100, confidence 0..1, категория, причины и рекомендации. Ошибка API не становится результатом. Промпт требует оценивать признаки конкретного ввода, а не считать любое сообщение опасным.

6. **URL Check.** Нормализация http/https; признаки HTTP, IP, длины, @, поддоменов, сокращателей, Unicode/punycode, цифр в хосте, порта, TLD и ключевых слов. google.com и подозрительный пример имеют разные наборы признаков, это проверено тестом. Признаки передаются AI как подсказки, не как доказательство; приложение не загружает проверяемый сайт и не заявляет проверку базы репутации URL.

7. **Phone Check.** Ручной ввод/буфер, валидация и нормализация KZ/международных номеров, код страны, источник/статус репутации, число доступных отметок и рекомендации. Без API — unknown, недостаточно данных, riskScore=null, а не ноль или 87. Описание разговора анализируется AI с доступной репутацией. Адаптер HTTPS reputation API и кэш до 24 часов реализованы; настоящий поставщик базы пользователем не подключён. Просроченная запись и отказ API не превращаются в отметку мошенничества.

8. **QR Scanner.** mobile_scanner 7.4.2, настоящая камера, рамка, фонарик при наличии, отказ в разрешении, переход в настройки, остановка по lifecycle/после распознавания и защита от дублирования. Декодируются URL, текст, телефон, SMS, email, Wi-Fi, контакт, платёжные данные и неизвестные схемы. Пароли Wi-Fi и контактные данные не передаются в AI. Ссылка открывается только явной кнопкой после анализа, с дополнительным подтверждением при высоком риске/низкой уверенности; платежи, звонки и SMS не исполняются. На эмуляторе отдельно проверены запуск CameraX и нативное ML Kit-декодирование двух QR-изображений. Наведение физической камеры телефона на бумажный QR не проверялось.

9. **CallScreeningService.** Kotlin-сервис и MethodChannel. Системная роль запрашивается кнопкой; без неё Flutter работает. До respondToCall нет AI/сетевых запросов, используется свежий локальный кэш. По умолчанию allow; блокировка лишь при opt-in, confirmed flagged и confidence≥0.95. Нативные события импортируются при запуске/возврате, подтверждаются после сохранения, дубли ID исключаются. Подтверждение после durable storage и повторный импорт покрыты Flutter-тестом. Проверены 8 Kotlin-тестов политики и native status без роли. Системную роль автоматически не назначали; фактический входящий звонок с выданной ролью и реальной reputation-базой не проверялся. Ограничения платформы описаны в [Android CallScreeningService](https://developer.android.com/reference/android/telecom/CallScreeningService).

10. **Разрешения.** Добавлены CAMERA и POST_NOTIFICATIONS, optional camera feature; сервис защищён android.permission.BIND_SCREENING_SERVICE. INTERNET существовал. CAMERA запрашивается при QR, роль — по кнопке, уведомления — отдельно. READ_CONTACTS, READ_SMS и READ_CALL_LOG отсутствуют. Для автоматической проверки preview тестов камера временно разрешалась только в тестовом эмуляторе; интеграционный запуск удалил тестовый пакет после завершения. minSdk остался 26; роль доступна с Android 10 при поддержке устройства. NDK и версии Gradle не менялись.

11. **Реальный AI.** После получения ключа он сохранён только в локальном `.env`. Выполнен настоящий live-тест с USE_MOCK_AI=false: 5 HTTP-запросов, строгий JSON и проверки различия результатов — All tests passed. Обычное сообщение: risk 0, confidence 0.9; запрос SMS-кода: 75 / 0.8; https://google.com: 0 / 0.9; подозрительный HTTP URL: 75 / 0.8; сообщение о выигрыше с комиссией: 75 / 0.8. Это фактические ответы провайдера на момент проверки; последующие оценки могут отличаться. Ошибки не подменяются mock. Ключ не выводился в результаты и не добавлялся в распространяемые APK/ZIP. Опубликованный в чате ключ рекомендуется заменить.

12. **Конфигурация.** `.env.example` содержит AI_API_KEY (пустое), AI_API_URL=https://api.openai.com/v1/chat/completions, AI_MODEL=gpt-4o-mini, USE_MOCK_AI=false; дополнительные PHONE_REPUTATION_API_URL/KEY пустые. Сохраните личный ключ в локальный `.env` и пересоберите приложение. В передаваемом APK/ZIP оба ключа пустые; это проверено чтением упакованного asset. `.env` можно извлечь из APK: для публикации нужен backend proxy, как описано в README.

13. **Дополнительные API.** Текст/URL и AI-объяснения требуют работающего AI-аккаунта с доступом к выбранной модели. Настоящая репутация номеров требует отдельного настроенного reputation API. Камера, декодирование QR, нормализация номера, история, настройки и нативная call-screening инфраструктура не требуют AI-запроса. Без reputation API подтверждённой блокировки новых неизвестных номеров не будет.

14. **flutter analyze.** Итоговый запуск: No issues found. `flutter clean`, `flutter pub get`, `dart format .` выполнены. Промежуточный обход build-файлов Windows при форматировании дал ошибку длинного пути; после clean полный format прошёл. Это не осталось ошибкой исходников.

15. **flutter test.** 26 тестов пройдено, 1 live-тест явно пропущен. Включены JSON/score/confidence, ошибки API, URL, номера/QR, репутация/срок кэша, durable импорт звонков, история, UI RU/KK на 360×640, 390×844 и 412×915. Дополнительно: 8 Kotlin-тестов — BUILD SUCCESSFUL; два Android native integration-сценария — passed (декодер/номер/роль и камера); сценарий onboarding→проверки→история→RU/KK→тёмная тема через flutter drive — passed. Автоматические тесты используют отдельные fixture-ответы с явной маркировкой, кроме собственно нативной камеры/декодера. Дополнительно после подключения ключа отдельно запущен `flutter test test/live_ai_test.dart --dart-define=STOPSCAM_LIVE_TEST=true`: 1 live-тест с пятью настоящими запросами пройден.

SHA-256: `3a7c39cd6337cab5d523b60ad028add9754e1b7b3b2f48107bad7d2e6a158854`. Обычный запуск через flutter run --no-resident с собранным APK завершился успешно (exit 0); приложение установлено и открыто в emulator-5554, foreground MainActivity подтверждён. Главный экран с четырьмя действиями проверен визуально и сохранён в previews/05-home-updated.png. Установку на физическое устройство и магазинную release-публикацию не выполняли.

В архив исходников не включены build, .dart_tool, .gradle, персональные настройки IDE и секретный локальный `.env`. Вложенный `.env` создан из пустого шаблона. Старые сохранённые данные читаются без обязательного confidence и получают недостающие метаданные типа/ввода/даты из записи истории.


После подключения ключа выполняется отдельная личная debug-сборка для текущего эмулятора. Её `.env` содержит ключ: файл `stopscam/build/app/outputs/flutter-apk/app-debug.apk` нельзя распространять. Общий `outputs/StopScam.apk` остаётся без ключа, его контрольная сумма выше относится именно к передаваемой версии. Архив исходников также содержит только пустой шаблон `.env`.
